    00

    全体の流れ

    今回つなぐ部品は次のとおりです。のあ（ローカルLLM）が考え、ai-player.mjs がその指示をMCPツール呼び出しに変え、server.mjs がブラウザのゲーム画面を操作します。

    Ollama（のあの頭脳）⇄ ai-player.mjs⇄ MCP ⇄ server.mjs→ Chromium の窓（ゲーム画面）→ OBS

    問題が起きたときに切り分けやすいよう、「LLMなしで動くか」→「LLMをつないで動くか」→「配信に載るか」の順に確かめます。

    • タスクマネージャー（Ctrl+Shift+Esc）→「パフォーマンス」→「GPU」→「専用GPUメモリ」。NVIDIAなら PowerShell で nvidia-smi でもわかります。手順06でモデルを選ぶときに使います。

    01

    ファイルを置く

    5分

    プロジェクトの共有フォルダにある game と mcp の2つのフォルダを、PCの同じ親フォルダの中に並べて置きます。server.mjs は「自分の1つ上の game\frontier-war.html」を探すので、並び方が大事です。

    D:\dev\frontier\
├─ game\
│   ├─ frontier-war.html
│   ├─ art\      （画像 42個）
│   └─ audio\    （BGM・効果音 9個）
└─ mcp\
    ├─ server.mjs       ├─ ai-player.mjs    ├─ notes.mjs
    ├─ game-api.js      ├─ selftest.mjs     ├─ notes-test.mjs
    ├─ package.json     ├─ README.md
    ├─ noa-player.mjs   （ai-player.mjs の旧名。同じものが動きます）
    └─ TEST-GUIDE.html  （この手順書。オフラインでも開けます）

    • zip の中身は共有フォルダの game と mcp をそのまま frontier フォルダに入れたものです。プログラムはフォルダの場所を決め打ちしていないので、game と mcp が並んでいれば D:\dev の下のどこでも動きます。

    • 以降のコマンドは、特に書いていなければこの mcp フォルダで打ちます。プロンプトが PS D:\dev\frontier\mcp> になっていればOKです。

    Dドライブで動かすときの注意

    PowerShell なら cd D:\dev\frontier\mcp だけでドライブも切り替わります（コマンドプロンプトの場合は cd /d D:\dev\frontier\mcp）。

    このフォルダ以外に、Chromium（約600MB、%LOCALAPPDATA%\ms-playwright）と Ollama のモデル（数GB〜、%USERPROFILE%\.ollama\models）は既定で C ドライブに入ります。C の空きが少ないときは、インストールの前に次を打って PowerShell を開き直すと D に入ります。

    setx PLAYWRIGHT_BROWSERS_PATH D:\dev\ms-playwright
setx OLLAMA_MODELS D:\dev\ollama-models

    OLLAMA_MODELS を変えたら、Ollama をトレイから「Quit Ollama」で終了して起動し直します。

    フォルダ名に日本語や空白が入っていても動くように、テスト用スクリプト（selftest.mjs）の不具合を直しておきました。それでも、トラブルを減らすため英数字だけのパスにしておくのが無難です。

    02

    Node.js を入れる

    10分

    • インストーラーの選択肢はすべて既定のままで大丈夫です。「Tools for Native Modules」のチェックは不要です。winget が使えるなら、次の1行でも入ります（「winget は認識されません」と出たら winget のない PC なので、.msi のほうで入れてください）。

      winget install OpenJS.NodeJS.LTS
    • node -v
npm -v

      v20 以上と表示されればOK（v22 / v24 なら安心）。こちらの確認環境は v22 です。

    「このシステムではスクリプトの実行が無効になっているため、npm.ps1 を読み込むことができません」と出たら

    Windows の初期設定で PowerShell のスクリプトが止められています。自分のユーザーだけ許可する次のコマンドを打ち、Y で答えてください（以後は不要）。

    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

    設定を変えたくなければ、npm の代わりに npm.cmd、npx の代わりに npx.cmd と打っても動きます。

    03

    部品（npm と Chromium）を入れる

    5〜10分
    • cd D:\dev\frontier\mcp
npm install

      MCP SDK・Playwright・zod が node_modules に入ります（約40MB）。最後に added ○○ packages と出ればOK。npm notice の行は無視してかまいません。

      ゲーム専用のブラウザを %LOCALAPPDATA%\ms-playwright に入れます。普段使いの Chrome とは別物なので、Chrome の設定や拡張機能には影響しません。

    04

    LLMなしで動作確認する

    5分

    簡単なボットがMCPツールを通してゲームを遊びます。ここが通れば「ゲーム・MCPサーバー・ブラウザ」の部分は正常です。

    • npm test

      こちらの環境で約30秒。最初に 27 tools、続いて ターン1 資金160 … とターンが進み、最後に次の2行が出れば成功です。

      最終：ターン18 資金1678 over=lose 自国惑星1 異生体=true
ツール呼び出し 339 回、拒否 10 回

      ボットは単純なので、負けて途中で終わること（over=lose）や、✗ battle_state: 戦闘中ではありません のような ✗ 行が混じるのは正常です。「押せない操作をしたら理由つきで断られる」仕組みが働いている印です。

    • $env:TURNS=5; node selftest.mjs --show

      Chromium の窓に「辺境星系戦記」が開き、移動のハイライト・戦闘アニメ・右上の「のあ：〇〇」・画面下の字幕「テストを始めるよ！」が見えればOKです。BGMも鳴ります。終わると窓は自動で閉じます。途中でやめるときは Ctrl+C。

      終わったら Remove-Item Env:TURNS で設定を消しておきます（PowerShell を閉じても消えます）。

    • npm run test:notes

      にせのLLMを立てて ai-player.mjs を4回走らせ、反省メモの保存と読み込みを確かめます。約20秒。✓ が8行並び、✗ がなければ成功です。

    ここまで通れば、残りは「LLMをつなぐ部分」だけです。この先で止まったら、原因はほぼ Ollama かモデルの設定です。

    05

    Ollama を入れて、コンテキストを広げる

    10分

    別のPCの Ollama を使う場合（例：のあが動いている 192.168.0.75）

    デスクトップに Ollama は要りません。この手順05と06は飛ばし、次の3つだけ確かめてください。

    • curl.exe http://192.168.0.75:11434/v1/models

      一覧の "id" が --model に渡す名前です。つながらないときは、向こうの Ollama が自分のPCからしか受け付けない設定になっています。OLLAMA_HOST=0.0.0.0:11434 を設定して再起動し（Linux の systemd なら sudo systemctl edit ollama で [Service] の下に Environment="OLLAMA_HOST=0.0.0.0:11434"）、ファイアウォールで LAN からの 11434 番だけを許可します。

    • コンテキスト長はサーバー側の設定で決まります。足りないとき（192.168.0.75 は既定で 8192 でした）は、普段のモデルはそのままに、コンテキストだけ広げたゲーム用のコピー noa-game をデスクトップから作れます。

      $body = @{ model="noa-game"; from="noa:latest"; parameters=@{ num_ctx=16384 }; stream=$false } | ConvertTo-Json
Invoke-RestMethod http://192.168.0.75:11434/api/create -Method Post -Body $body
    • node ai-player.mjs --base-url http://192.168.0.75:11434/v1 --model noa-game --think none --turns 3

      --think none はモデルが返事の前に考える時間を省きます。thinking 対応のモデル（noa・gemma4 など）では、これを付けると1手ごとの待ち時間が大きく減ります。

      先に $env:LLM_BASE_URL="http://192.168.0.75:11434/v1" を打っておけば、そのPowerShellでは --base-url を省けます。

    普段ののあと同時に使うと、返事が順番待ちになって遅くなります。Ollama には認証がないので、ルーターでポートを外に開けないでください。

    • ollama --version

      バージョンが表示されればOK。Ollama はトレイに常駐して http://127.0.0.1:11434 で待ち受けます。ai-player.mjs の既定の接続先もここです。

    • のあへの指示とルールで約3千字、状況テキストで2〜4千字あり、ツールの説明も加わります。こちらで実測したところ、1ターン目の最初の呼び出しだけで約5,000トークンでした。ターンの中で操作を重ねるほど増えるので、既定の 4096 では足りません。次のどちらか一方で設定します。

      A. Ollama の画面で設定する（簡単）

      トレイのアイコン → Ollama の画面を開く →「Settings」→「Context length」のスライダーを 16k（または 32k）にします。

      B. 環境変数で設定する

      setx OLLAMA_CONTEXT_LENGTH 16384

      打ったあと、トレイのアイコンを右クリック →「Quit Ollama」で終了し、スタートメニューから Ollama を起動し直します（setx は新しく起動したものにだけ効きます）。

    設定が効いているかは、手順06でモデルを動かした直後に ollama ps を打つとわかります。CONTEXT 欄が 16384（または 32768）なら成功です。

    06

    モデルを選んでダウンロードする

    10〜30分

    必須条件はツール呼び出し（function calling）に対応していることです。戦術戦闘では座標を扱うので、小さすぎるモデルは失敗が増えます。VRAMに収まる中で大きめを選んでください。

    VRAMおすすめダウンロード量メモ
    8GBqwen3:8b約5GB動作確認には十分。戦闘のミスはやや多め
    12〜16GBqwen3:14b約9GBREADME の例と同じ。まずはこれ
    16GB以上gpt-oss:20b約14GB比較用の2本目に
    24GBqwen3:30b約19GB速さと賢さのバランスがよい
     
    • ollama pull qwen3:14b
    • ollama show qwen3:14b

      Capabilities の欄に tools があればOKです。ollama.com のモデル一覧でも「tools」の札がついているものを選びます。

    • ollama run qwen3:14b "こんにちは。ひとことで自己紹介して"
ollama ps

      ollama ps の PROCESSOR が 100% GPU なら理想です。CPU/GPU に分かれていると、はみ出した分だけ遅くなります。そのときは1段小さいモデルか、コンテキストを 16384 に下げます。

    README の比較例にある gemma3 はツール呼び出しに対応していません。つなぐと LLM API 400: … does not support tools で止まります。モデル比べをするときは、tools 対応のモデル同士で比べてください。

    LM Studio を使う場合は --base-url http://127.0.0.1:1234/v1 --model <LM Studioのモデル名> を付けます。

    反省メモを確かめる

    5分

    ローカルLLMはプレイ中に学習しないので、プレイを振り返って「次に活かすこと」を書かせ、次のターンと次のゲームの最初に読ませています。書き直すのは、ゲーム終了時・10ターンごと・--turns で止まったとき・Ctrl+C のときです。

    • ## 反省メモ（大事な順）
- 爆装を2以上積んだ艦隊で惑星を攻める
- 通信ウィンドウが出たら先に dismiss_dialog してから end_turn
## 戦績（新しい順）

      手で直したり、項目を消したりしてかまいません。最大1200字に収まるよう、本人が要らない項目を消していきます。

    • node ai-player.mjs --model gpt-oss:20b --name ジーピー

      メモは notes\ジーピー.md に別に育ち、字幕の名前も「ジーピー」になります。のあのメモを別のモデルに引き継ぐなら --notes notes\のあ.md を付けます。

    09

    操作盤で連続プレイと録画をする

    15分〜

    ブラウザで開く操作盤から、試行回数を決めて続けて遊ばせ、試行ごとに自動で録画します。1試行＝1ゲームで、前の試行で書いた反省メモが次の試行の最初から効きます。録画に OBS は要りません（音は入りません）。

    • 新しい frontier-mcp-kit.zip を展開し、中の frontier フォルダを D:\dev にドラッグして「ファイルを置き換える」を選びます。notes（反省メモ）と node_modules は zip に入っていないので、そのまま残ります。

      エクスプローラーで D:\dev\frontier\mcp を開き、「操作盤を開く」（操作盤を開く.cmd）があればOKです。

    • 黒い窓が出て、いつものブラウザで「AIプレイ操作盤」が開くと、黒い窓は自動で閉じます。プレイ中にブラウザのタブを閉じても、プレイは裏で続きます。タブを閉じてプレイもしていなければ、90秒ほどで操作盤は自動で終わります（もう一度ダブルクリックすれば開き直します）。はじめての1回は部品のダウンロードで数分かかるので、黒い窓は閉じずに待ちます。「セキュリティの警告」が出たら「実行」を、「Windows によって PC が保護されました」と出たら「詳細情報」→「実行」を押します。

      操作盤の右上の「デスクトップに置く」を押すと、デスクトップにショートカットができます。次からはそれをダブルクリックします。終えるときは右上の「終了」です。

    • LLM を使わずに、ゲームと MCP サーバーが動くかを確かめます（窓なしで10ターン、1〜2分）。手順04の npm test と同じことを、操作盤からできます。

    • 欄入れるもの
      LLM の URLhttp://192.168.0.75:11434/v1
      モデル「一覧」を押して noa-game を選ぶ（一覧が出れば、Ollama のPCにつながっています）
      プレイヤーの名前のあ
      考える量考えない（速い）＝ これまでの --think none
      試行回数／1回の上限ターン2 ／ 3（お試し。空欄にすると決着まで）
      反省メモ読んで、書き足す
      録画するチェックを入れる

      入れた設定は次に開いたときも残ります。

    • 操作盤の「ログ」にこれまで PowerShell に出ていた行が流れ、「進行」に試行・ターン・資金・経過時間が出ます。試行の終わりには ── 試行 1/2 終了：ターン上限（ターン3） 録画 のあ_…_1of2.webm と出ます。

    • 動画は D:\dev\frontier\mcp\recordings にも保存されています（WebM、1時間で約450MB）。字幕と行動表示は映りますが、音は入りません。「反省メモ」タブでは、試行のたびに書き直されたメモが見られます。

    • 「この試行で終わる」は今のゲームを最後まで遊んでから止めます。「いま止める」は反省メモを書いてから止めます（返事待ちの途中なら1分ほどかかります）。「強制終了」はメモを書かずにすぐ止めます。操作盤ごと終えるときは右上の「終了」です。

    • 戦績の棒グラフ（高さ＝到達ターン、緑＝勝利・赤＝敗北・橙＝途中）で、試行を重ねて上達しているかがわかります。窓を出さずに裏で回すなら「ゲームの窓を出さない」にチェック（録画はできます）。

    OBS で配信しながら使うとき：試行ごとにゲームの窓が開き直しますが、窓のタイトル（辺境星系戦記）は同じなので、OBS のウィンドウキャプチャは自動で映り直します。映らなくなったら、ウィンドウキャプチャの「ウィンドウの一致優先度」を「ウィンドウタイトルに一致する必要があります」にします（操作盤も Chrome で開いていると、別の窓を拾うことがあるため）。

    うまくいかないとき
    症状対処
    黒い窓に「Node.js が見つかりません」手順02の Node.js を入れてから、もう一度ダブルクリックします
    黒い窓に「準備に失敗しました」インターネットにつながっているか確かめて、もう一度ダブルクリックします

    画面右上が「操作盤が止まっています」「操作盤を開く」をダブルクリックし直します（戦績と設定は残っています）
    10

    OBS に映す

    10分

    のあを動かしている間に設定します。--turns なしで動かしておくと作業しやすいです。

    • 既定は 1280x720 です。1920x1080 で配信するなら、のあ側にも -- --size 1920x1080 を付けます。

    • ウィンドウの一覧では [chrome.exe]: 辺境星系戦記 のように表示されます。キャプチャ方法は「Windows 10 (1903以降)」を選びます。「BitBlt」だと Chromium の画面が真っ黒になります。

    • ウィンドウキャプチャの「音声をキャプチャ」にチェックするか、別に「アプリケーション音声キャプチャ」を追加して同じ窓を選びます。音声ミキサーにメーターが動けばOKです。

    • どちらもゲーム画面の中に描いているので、OBS 側で文字のソースを足す必要はありません。
