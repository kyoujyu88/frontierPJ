# 辺境星系戦記 MCPサーバー（のあ配信用）

AIエージェント（のあ）が MCP ツールで「辺境星系戦記」を遊び、その画面をそのまま配信するための一式です。

```
のあ（MCPクライアント）
   │  stdio または Streamable HTTP
   ▼
server.mjs（MCPサーバー）──Playwright──▶ Chromium の窓（ゲーム画面）──▶ OBS でウィンドウキャプチャ
                                          └ game-api.js を注入（window.gameAPI）
```

- ゲーム本体（`../game/frontier-war.html`）は**書き換えずに**使います。`game-api.js` をページに後から差し込み、画面のボタンと同じ関数を同じ条件で呼びます。
- のあの操作は画面上でも見えます。移動先のハイライト、改装画面や造船所の表示が出ます。右上には「のあ：〇〇」と行動内容が出ます。
- **戦術戦闘はオート**です。艦隊を攻め込ませたり敵に襲われたりすると、ゲーム本体のオート戦闘で艦が自動で動き、決着して作戦卓に戻ってから結果が返ります。のあは戦闘を1隻ずつ操作しないので、戦闘に時間がかかりません（1戦あたり演出込みで1分ほど）。勝敗を分けるのは、戦う相手の選び方・修理・改装・陣形・旗艦の選び方といった事前の準備です。オートは陣形（方陣なら護衛が旗艦の隣に残る、鶴翼なら回り込みを重く見る）と艦の配分（ミサイル寄りは距離を保つ、旗艦と傷ついた艦は控える）に合わせて動くので、準備がそのまま戦い方になります。状況テキストの移動先と迎撃欄には、相手のドクトリン・戦力比・陣形の目安（オートでの勝率から）が付きます。1隻ずつ操作させたいときは `server.mjs` に `--manual-battle` を付けます（下の「オプション」）。
- `say` ツールでのあのセリフを画面下に字幕表示できます。

## セットアップ（配信するPCで）

Node.js 20 以上が必要です。

```sh
cd mcp
npm install
npx playwright install chromium
npm test            # 動作確認（ウィンドウなしで30ターン）
npm run test:regress   # ゲーム本体の回帰テスト（数秒）
npm run test:api   # MCP の入力スキーマと同時呼び出しの回帰テスト（十数秒）
node selftest.mjs --show   # 窓を出して演出つきで眺める
MANUAL=1 npm test   # 戦闘を battle_* で1隻ずつ操作する版（--manual-battle）の動作確認
```

`mcp/` と `game/` は同じ親フォルダに置いてください（ゲームの場所は `--game` で変えられます）。

## 家のローカルLLMで遊ばせる（ai-player.mjs）

Ollama・LM Studio・llama.cpp server などの **OpenAI互換API** に直接つなぐプレイヤーです。MCPクライアントを別に用意しなくても、これ1本で「のあが考える → ツールで操作 → 画面に字幕」が回ります。

```sh
# Ollama（既定 http://127.0.0.1:11434/v1）
node ai-player.mjs --model qwen3:14b

# LM Studio
node ai-player.mjs --base-url http://127.0.0.1:1234/v1 --model <モデル名>

# のあの人格ファイルと、ゲーム側のオプション（-- の後ろは server.mjs に渡る）
node ai-player.mjs --model qwen3:14b --persona noa.txt -- --pace 900 --size 1920x1080
```

- のあが返した地の文は、そのまま画面下に字幕で出ます（`<think>…</think>` は消します）。
- ツール呼び出しを地の文に書いてしまうモデル（gemma4 など）にも対応しています。`move_fleet(fleet_id=1, to=2)` や `call:end_turn{}` は拾って実行し、`say{text:「…」}` が並んだときや、行の頭に `say "…"` と書いたときは1件ずつ字幕に出します（記法そのものは字幕に出しません）。括弧を付けずに `end_turn` とだけ書いた行も字幕には出さずに実行し、「これで end_turn するね」のような文の中のツール名は「これでターン終了するね」と日本語の操作名に置き換えます。続けて話すときは、前のセリフが読める長さ（最大6秒）だけ待ってから次を出します。
- 状況は短い日本語のテキスト（`get_summary`）で渡します。**コンテキスト長が分かるときは、ターンをまたいで会話を続けます**（前のターンの会話の後ろに新しい状況を足すだけ）。ターンごとに会話を作り直すと、毎ターン最初の返事でプロンプト全体（約7千トークン）を読み直すので、2026-11-16 のログでは毎ターン 約11秒かかっていました。コンテキスト長は `--ctx` か、サーバーに聞いて調べ（Ollama は `/api/ps` の読み込み中のモデルの長さ、llama.cpp は `/props` の `n_ctx`、LM Studio は `/api/v0/models` の `loaded_context_length`、vLLM・OpenRouter などは `/v1/models` の `max_model_len`・`context_length`）、「今の長さ＋新しい状況＋1ターン分の余裕」が9割に収まる間だけ続けます。余裕は、最近3ターンで会話が実際に伸びた分の平均の1.1倍です（測るまでは3千トークン）。続けるターンに足す状況テキストは、**惑星の一覧と最近の出来事を前のターンから変わった行だけ**にします（内政の候補・自軍艦隊・他勢力の艦隊は全部。`sumdiff.mjs`）。`--keep-turns`（既定4）ターン続けたら作り直します。分からないとき・`--no-keep-context`・`--manual-battle` のときは、今までどおり毎ターン作り直します。ターンの途中で9割を超えそうになったら、そのときの状況で作り直します。
- 作り直すときは、前の2ターンに**したこと**（成功した操作と戦闘の結果）を1ターン1行で渡します。以前は前のターンの最初のセリフを渡していましたが、小さなモデルはそれをそのまま繰り返し、採掘所のある星に3ターン続けて採掘所を建てようとしました。
- ターンの中では、会話は後ろに足すだけで、前に送ったメッセージは書き換えません。操作のたびに状況テキスト全体を付け直す代わりに、返り値の「のこりの手」（いまの資金で払える内政・未行動の艦隊）だけを足します。「のこりの手」は操作のたびに付くので短くしてあり、施設は建てられる星ごとにまとめ（例 `mineは星2、sats/lab/flakは星0/1/2`）、艦隊の行き先は、このターンに一度知らせた艦隊なら説明を省いて `move_fleet(fleet_id=6, to=3か7)` の形だけ書きます。ローカルLLMは会話の前のほうが変わるとプロンプト全体を読み直すためです（2026-11 のプレイログ23本の実測で、読み直しのある返事は平均 10.7秒、ない返事は 1.4秒。以前は戦闘や通信のたびに読み直していました）。`-- --manual-battle` のときだけは、盤面のテキストを最新の1つだけ全文で送り、古いものを縮めます。
- 操作ツールの `say` 引数に書いたひとことは、地の文と同じく字幕に出します（セリフと操作が1回の返事で済みます）。`:build_ship` のように記号の付いたツール名は記号を外し、`replace_ship` は `build_ship` の `replace=true` に読み替えます。
- 戦闘はオートで決着するので、のあには「出来事」として結果（例：`戦闘「ミラ 攻略戦」：勝利（9ラウンド・自軍の損失1/4隻・敵の撃破3/3）`）と、「のこりの手」・艦隊の残りの耐久が届きます。反省メモの戦績にも数えます。
- 中身が空の返事（話さず、ツールも呼ばない）は会話に積みません。1回目は行き先も全部書いた「のこりの手」を見せて、ツールを1つだけ呼ぶよう頼みます。2回続いたら、ツールを渡さずに聞いて手を `move_fleet(fleet_id=6, to=7)` のような文字で書いてもらい、それを実行します（トークンは出ているのに中身が空なので、ツール呼び出しを Ollama が読み取れずに捨てていると見ています。ツールを外すとプロンプトの読み直しが1回入ります）。それでも空なら自動進行にします（2026-11-17 のログでは空の返事が1ゲーム13回、ターン8で3回続いて3艦隊が動かないままターンが終わった）。地の文だけの返事にも「のこりの手」を添えて促します。
- ツール呼び出しを使わずに、手を文字で書いた返事も実行します。関数の形（`move_fleet(fleet_id=6, to=7)`）のほか、ツール名をキーにした JSON（`[{"say": "…"}, {"build_ship": {"fleet_id": 1}, "say": "…"}]`）や `{"name": "move_fleet", "arguments": {…}}` も拾い、say はセリフにします（2026-11-17 のログでは、手を JSON の配列で書いた返事が空の返事と数えられていた）。返事が上限で切れたとき（finish=length）は、引数が途中で終わった最後の呼び出しだけ実行しません（プレイログの `cut`）。
- のあが考える回数が `--max-steps`（既定40）を超えたり、黙り込んだりしたら、残りを自動で片付けて先へ進めます。作戦卓では1ターンごとに数えます（`-- --manual-battle` で戦闘を操作させるときは、戦闘は1戦ごとに数え、上限を超えたらその戦闘だけ自動で片付けます）。配信が止まらないための保険です。
- LLMにつながらないとき（モデル名の違い・ツール非対応も）は、自動で遊び続けずに止まります。`LLM API 400` などその場かぎりのエラーは、そのターンだけ自動で進めて続けます（3ターン続いたら止まります）。
- プレイを振り返って**反省メモ**を書き、次のプレイに活かします（下の「遊ぶほど上手になる」）。

**モデルについて**：ツール呼び出し（function calling）に対応したモデルが必要です（Ollama なら `ollama show <モデル>` の Capabilities に `tools` があるもの。`gemma3` などは非対応で `LLM API 400: … does not support tools` になります）。システムプロンプトとルールで約3千字、状況テキストで2〜4千字になるので、**コンテキストは16k以上**にしてください（Ollama なら `OLLAMA_CONTEXT_LENGTH=16384 ollama serve`）。VRAM に余裕があれば 32k にすると、ターンをまたいで会話を続けられる回数が増え、毎ターン最初の返事が速くなります。戦術戦闘はオートなので、座標を扱う操作はありません（`--manual-battle` で操作させると、小さすぎるモデルでは失敗が増えます）。失敗しても理由が返るので、次の手で取り返せます。

### 使っている LLM の詳細（開始ログ）

プレイの始めに、使っているモデルの詳細を画面（操作盤のログ）とプレイログに出します。Ollama なら次のように出ます。

```
LLM：noa-game（gemma3・25.8Bパラメータ・量子化 Q4_K_M・ツール・考える対応）　Ollama 0.13.0
  コンテキスト長：モデル本来の上限 131,072／Modelfile の num_ctx 16,384
  返事の上限：512（--max-tokens。Modelfile の num_predict 200 より優先）
  GPU：RTX 4090 24GB（--gpu の指定）
読み込み状態：コンテキスト長 24,576・メモリ 20.0 GB：GPU（VRAM）15.0 GB 75%／メインメモリ 5.0 GB 25%・GPU RTX 4090 24GB
  ⚠ モデルの 25% がメインメモリに載っていて、その分は CPU で計算するので遅くなります（…）
```

- 1〜3行目は `/api/show` と `/api/version`（読み込み前でも分かる）。「モデル本来の上限」は学習時の最大長、`num_ctx`・`num_predict` は Modelfile に書いた値です。
- 「読み込み状態」は最初の返事のあと（モデルが読み込まれてから）`/api/ps` で調べます。コンテキスト長は**実際に確保された長さ**で（`OLLAMA_CONTEXT_LENGTH` や `num_ctx` の結果）、会話を続ける判断にもこの値を使います。メモリは `ollama ps` の PROCESSOR 欄と同じ計算です（重みと会話用の領域の合計のうち、GPU のメモリに載った割合）。一部がメインメモリにはみ出すと遅くなるので注意を出します（GPU をまったく使っていないときは「GPU を使っていません」と書くだけ）。`/api/ps` にモデルが見つからなかったときは、次のターンにもう一度調べます（3回まで）。
- **GPU の機種名は Ollama の API では分かりません。** 操作盤の「詳しい設定」の「GPU の名前」（`--gpu`）に書くとログに残ります。Ollama が同じ PC（`localhost`）のときだけ、空欄でも `nvidia-smi` で機種名と VRAM の大きさを調べます（別の PC の Ollama だと、こちらの PC の GPU を拾ってしまうので調べません）。
- 操作盤の戦績の「モデル」欄にも、読み込み状態（コンテキスト長とメモリ）を小さく出します。Ollama 以外のサーバーでは詳細は出ません（プレイには影響しません）。

### 遊ぶほど上手になる（反省メモ）

ローカルLLMはプレイ中に学習しないので、そのままだと毎回はじめて遊ぶ状態になります。そこで、プレイの記録を本人に読ませて「次に活かすこと」を書かせ、次のプレイの最初に読ませます。

1. プレイ中、ターンごとの要点を記録し、数字を数えます（勝利ターン・操作失敗・資金不足・行動済みの失敗・内政なしのターン・戦闘の敗北・最大星・収入）。
2. ゲームが終わったとき、`--reflect-every` ターンごと、`--turns` で止まったとき、Ctrl+C で止めたときに、LLMが振り返ります。渡すのは、番号つきのいまのメモ・**今回と前回のゲームの数字**・**前に決めた目標の答え合わせ**（達成／未達成はこちらで判定）・ターンごとの記録です。
3. メモは丸ごと書き直さず、**差分**で直します。返事の「消す 番号：理由」「足す：新しい項目」だけを当て、1回に消すのも足すのも2項目まで（メモが空の最初だけ5項目まで）。書かなかった項目は残るので、役に立つメモが毎回入れ替わることはありません。
4. ゲームの終わりの振り返りでは、次のゲームの**目標**を決まった物差しと数字で書かせます（例：「目標：資金不足 3回以下」）。次のゲームではプロンプトに「今回の目標」として入り、終わったら答え合わせして戦績に「目標1/2達成」と残します。
5. 反省メモと目標は次のターンから、毎ターンのシステムプロンプトに入ります。同じゲームの後半にも、次のゲームにも効きます。
6. 書き終えたら、視聴者へのひとこと（感想）を字幕に出します。

なぜこうしたか：2026-11-14〜15 のプレイログで、丸ごと書き直していたころのメモあり11試合とメモなし10試合を比べたら、勝ったターン（中央値 30 と 30.5）も失敗率（17.9% と 16.8%）も変わりませんでした。メモは毎回ほぼ全部入れ替わり、「常に確認する」のような一般論ばかりでした。数字と目標を渡して、効いた項目を残せるようにしています。

反省メモは `notes/<名前>.md` に、こんな形で残ります。手で読んだり、直したり、項目を消したりできます。

```markdown
## 反省メモ（大事な順）
- 爆装を2以上積んだ艦隊で惑星を攻める
- 資金を使ったあとは「のこりの手」を見て、払える内政だけを選ぶ（「資金が足りなくなった手」に出た手は呼ばない）
## 目標（次のプレイで答え合わせします。物差し：勝利ターン・操作失敗・…）
- 資金不足 3回以下
## 前回の数字（最後に終わったゲーム。自動で書きます）
- 勝利ターン：30
- 操作失敗：7
## 戦績（新しい順）
- 2026-11-19 noa-game:latest 勝利 ターン30 最大9星 戦闘31回（勝26） 操作失敗7回（資金不足2） 内政なし0ターン 目標1/2達成
```

古い形式（丸ごと書き直していたころ）のファイルは、項目を読み込まずに戦績だけ引き継ぎます。もとのファイルは最初に `notes/<名前>.md.v1.bak` へ控えを残します。古い形式のまま `--notes-readonly`（操作盤の「読むだけ」）で遊ぶと、項目がないので「使わない」と同じ状態になります。一度「使う」で遊んで新しい形式のメモを作ってから固定してください。

目標の答え合わせと前回との比較は、勝敗が決まったゲームだけでします。途中の振り返り（`--reflect-every`）や途中で止めたときは「途中までの数字」だけを渡し、目標は変えません（少ない方が良い物差しは、早く止めるほど良く見えるため）。

**ほかのローカルLLMでも同じです。** 振り返りはツールを使わない普通のチャットで、返事の中の「消す」「足す」「目標」「感想」の行だけを拾います（`<think>` や前置きは無視）。「- 」の箇条書きで丸ごと書いてきたときは、いまのメモにない項目だけを「足す」として2つまで使います。何も拾えなかったときは前のメモを残します。メモは名前ごとに分かれるので、モデルを比べたいときは名前を変えます。

```sh
node ai-player.mjs --model qwen3:14b                     # notes/のあ.md を育てる
node ai-player.mjs --model gpt-oss:20b --name ジーピー     # notes/ジーピー.md（字幕の名前もジーピー）
node ai-player.mjs --model gpt-oss:20b --notes notes/のあ.md # のあのメモを別のモデルに引き継ぐ
```

戦績にはモデル名も残るので、同じ名前で途中からモデルを替えても、どのモデルで遊んだかがわかります。反省メモは最大1200字（`--notes-chars`）なので、コンテキストが小さいモデルでも溢れません。

配信で「上達したところ」を見せたいときは、育てたメモを `--notes-readonly` で固定する、または `--no-notes` と見比べると違いがわかりやすくなります。効いているかは、メモありとなしを数試合ずつ回して `npm run stats` で比べてください（集計の「反省メモ」の行に、その試合でメモを使ったかが出ます）。

LM Studio は自身もMCPクライアントになれるので、`server.mjs` を LM Studio の `mcp.json` に登録して、そのチャット画面から遊ばせることもできます（下の stdio 設定と同じ書き方）。

## 連続プレイと録画（操作盤 control.mjs）

ブラウザで開く操作盤から、AIに**決めた回数だけ続けて**遊ばせ、試行ごとに**自動で録画**します。OBS は要りません。コマンドを打たずに使えます。

- **Windows**：`mcp\操作盤を開く.cmd` をダブルクリック。はじめての1回は `npm install` と Chromium（録画用の ffmpeg 込み）を自動で入れます。操作盤は窓なしで裏で動き、既定のブラウザで `http://127.0.0.1:3940/` が開きます。もう動いていれば開くだけです。終えるときは画面右上の「終了」。タブを全部閉じたときも、プレイ中でなければ90秒ほどで自動で終わります（プレイ中なら、終わってから90秒後）。
- 画面右上：「動作確認」（LLMなしで selftest を10ターン）・「反省メモを開く」（メモ帳）・「録画フォルダ」・「デスクトップに置く」（ショートカット作成）・「終了」。
- コマンドで動かすなら `npm run ui`（= `node control.mjs`）。起動係は `launch.mjs`、操作盤の出力は `notes/.control.log` に残ります。

- 画面で LLM の URL・モデル（「一覧」で LLM から読み込める）・名前・考える量・**試行回数**・1回の上限ターン・反省メモの使い方・録画のオンオフを決めて「連続プレイを開始」。設定は次回も残ります。
- 1試行＝1ゲーム。試行ごとに `ai-player.mjs` を起動し直すので、毎回新しいゲームになり、**前の試行で書いた反省メモが次の試行の最初から効きます**。
- 「この試行で終わる」（今のゲームは最後まで）・「いま止める」（反省メモを書いてから止める）・「強制終了」（すぐ止める）で止められます。LLM につながらなくなったら、残りの試行はやめます。
- 「戦績」タブに試行ごとの結果（勝利・敗北・ターン上限・停止）、到達ターン、自動進行と操作失敗の回数、録画が並びます。到達ターンの棒グラフで、上達しているかが見えます。「反省メモ」タブは今のメモ、「録画」タブはその場で再生・保存、「プレイログ」タブはセリフや操作の記録と字幕・台本の取り出し（下の「プレイログ」）。
- 「ゲームの窓を出さない」にすると裏で回せます（録画はできます）。演出の間（pace）を 0 にすると最速ですが、録画は見づらくなります。
- 「詳しい設定」の**戦闘の演出の速さ**（既定2倍）で、戦闘・敵の移動・艦隊の移動の演出を速く流せます。2026-11-16 のログでは、AIプレイの時間の67%が戦闘の演出でした。2倍で1戦 約43秒→約22秒（`npm run test:speed`）。戦闘の中身と結果は変わりません。作戦卓の操作や通信の表示の長さは変わりません。「会話を続ける」（既定オン）は、上のとおりターンをまたいで会話を続けるものです。
- 操作盤はこのPCからだけ開けます（127.0.0.1 で待ち受け、Host ヘッダーを確かめる）。`npm run ui` で起動したときは、その窓を閉じるとプレイも止まります。ポートを変えるなら `node control.mjs --port 3941`、ブラウザを自動で開かないなら `--no-open`。
- 戦績の一覧は `notes/.control-history.json`、操作盤の設定は `notes/.control-settings.json` に残ります。

**録画について**：映像は Playwright の動画録画（`server.mjs --record`）、音はページの中で録ります（ゲームの音はすべて1つの AudioContext から出るので、出力へのつなぎ込みを横取りして MediaRecorder で Opus に録る）。試行が終わると `mux-audio.mjs` が、`npx playwright install chromium` で入る ffmpeg で両方を1本に重ねます（ストリームのコピーだけなので数秒）。追加のソフトは要りません。

- 1回の録画で3つのファイルができます。`<名前>.webm`（映像と音を合成したもの。ふだん見るのはこれ）、`<名前>.video.webm`（映像だけ）、`<名前>.audio.webm`（音だけ、Opus）。映像だけ・音だけのファイルはどちらも同じ時刻から始まるので、動画編集ソフトで頭をそろえて並べればそのまま合います。操作盤の「録画」タブの「映像だけ」「音だけ」から保存できます。合成したものと映像だけのものがあるので、容量は約2倍になります。
- **音ずれの直し（2026-11）**：以前は長く録るほど音が先に進んでいました。Playwright は届いた画面を 25fps に詰めるとき、コマごとに「前のコマからの時間×25」を四捨五入し、最低1コマは入れます。この丸めの誤差が積み重なり、動きの多い場面ほど映像が実際より長くなっていました（テスト用ページで60秒録ると映像が68秒になり、音が1分で7.5秒先に進んだ）。今は `video-clock.mjs` がコマを実際の時刻どおりに並べ直し（足りなければ繰り返し、多すぎれば捨てる）、音の録り始めを映像の0秒にそろえます。同じテストで、光と音の差は最初から最後まで±0.04秒（1コマ）以内です（`npm run test:recsync`）。

- 形式は WebM（VP8・25fps・約1Mbps＋Opus 128kbps）で、**BGM と効果音が入ります**。合成したものは1時間で約500MBです。字幕と行動表示は画面の中に描いているので映ります。
- 音を重ねるのは試行が終わった直後です。数秒のあいだは映像だけのファイルが見えます。重ねるのに失敗したときは映像だけを `<名前>.webm` にし（音は `<名前>.audio.webm` に残る）、理由を録画フォルダの `.mux-audio.log` に書きます。音を入れたくないときは `--no-record-audio`（そのときは `<名前>.webm` だけ）。
- 録画フォルダには、仕上げに使う覚え書き（`.rec-*.json`）と音（`.audio-*.webm`）が一時的にできます。Windows ではゲームが終わるとサーバーがすぐ止められることがあり、そのときは覚え書きが残りますが、操作盤が試行のたびに（操作盤を使わないときは次に `server.mjs --record` を起動したときに）名前を付け直して音を重ねます。
- ファイル名は `recordings/<名前>_<日時>_<n>of<回数>.webm`。YouTube にはそのまま上げられます。MP4 が要るときは変換してください。
- もっと高画質で残したいときは、これまでどおり OBS で録画します（下の「配信のしかた」）。

`ai-player.mjs` を直接動かすときも、`--` の後ろに付ければ録画できます。

```sh
node ai-player.mjs --model noa-game -- --record recordings
```

## プレイログ（動画編集用：セリフ・操作・戦闘の記録）

`ai-player.mjs` は試行ごとに、起きたことを時刻つきで `logs/<名前>.jsonl` に残します（操作盤から動かしたときは録画と同じ名前）。`--no-log` で止められます。

- **残すもの**：字幕に出したセリフ（表示秒数つき）・ターンの区切りと資金・ゲームの操作と結果（AIが選んだものと自動進行のもの、失敗の理由、出来事）・断った呼び出し・戦闘の結果・自動進行に切り替えた理由・エラー・反省メモの振り返り・勝敗・試行の終わり（結果と動画の名前）。
- **LLMとのやり取りも全文で残します**：送った文（システムプロンプト・状況テキスト・ツールの結果。システムプロンプトは変わったときだけ）と、返事を加工する前の全文（`<think>` や考えた部分の欄・ツール呼び出し・トークン数・かかった秒数）。字幕にならなかった発言や、モデルが何を考えていたかを後から確かめられます。
- **時刻は録画に合わせます**：録画しているときは、各行に録画の開始からの時間（`vms`）が付きます。録画しないときはプレイの開始からの時間（`ms`）。どちらにも実際の日時（`t`）が付きます。
- 録画した試行は、試行が終わると**動画の隣に同じ名前の字幕（`.srt`）**ができます。VLC などの再生ソフトは自動で読み込み、動画編集ソフト（DaVinci Resolve・Premiere・Vrew など）には字幕トラックとして読み込めます。BOM 付き UTF-8 なので Windows でも文字化けしません。
- ログは1試行で数百KB〜数MBです。自動では消さないので、要らなくなったら `logs` フォルダから消してください。

**操作盤で見る・取り出す**：「プレイログ」タブで試行を選ぶと、時刻つきで読めます。セリフ・ターン・戦闘・操作・進行・エラー・LLMとのやり取りを、チェックで出し分けられます。録画があるときは時刻を押すとその場面から再生します。「戦績」タブの「見る」からも開けます。次の形で保存できます。

| 取り出し | 中身 |
|---|---|
| 字幕 SRT / 字幕 VTT | セリフだけの字幕。表示時間はゲーム画面の字幕と同じ（次のセリフが出たらそこまで）。古いログに `say{text:「…」}` が並んだまま残ったセリフは、ここで1件ずつに分けます（表示時間は文字数で割り振り）。`end_turn` のような操作名だけのセリフは外し、文の中のツール名は日本語の操作名に置き換えます |
| 台本 TXT | 時刻・ターン区切り・セリフ・操作・戦闘・反省メモを1本の文章に。編集の下見や台本づくりに |
| 台本（LLM全文つき） | 台本に、LLM に送った文と返事の全文も入れたもの |
| チャプター | ターンごとの時刻（`0:00 はじまり`・`1:23 ターン2`…）。YouTube の概要欄に貼るとチャプターになる |
| 集計 TXT | 下の「集計」の表を文字で |
| JSONL | すべての記録（1行1件の JSON） |

**コマンドで取り出す**（mcp フォルダで）：

```sh
npm run logs                                   # 一覧（新しい順に番号つき）
node playlog.mjs 1 --format srt --out ep1.srt  # いちばん新しい試行の字幕
node playlog.mjs のあ_20261108 --format txt     # 名前の一部でも選べる。台本を画面に出す
node playlog.mjs 2 --format txt --all          # LLM とのやり取りも入れた台本
node playlog.mjs 1 --format chapters           # チャプター
```

形式は `srt`・`vtt`・`txt`・`chapters`・`stats`・`jsonl`。`--dir` で別のフォルダのログも読めます。

### 集計（モデルや設定を比べる）

プレイログから、テンポと操作の質の数字を出します。モデル・サーバー・設定を替えたときに、同じ物差しで比べるためのものです。操作盤では「プレイログ」タブの「集計」を開くと表で出ます。プレイの終わりにも、ログに `集計：1ターン59秒（LLM 22・移動と戦闘 32）・…` の1行が出ます。

```sh
npm run stats                      # いちばん新しい試行の集計
node playlog.mjs --stats 3 2 1     # 何本かを横に並べて比べる（左から書いた順）
node playlog.mjs 1 --format stats  # 集計を文字で（--out でファイルへ）
```

| 項目 | 中身 |
|---|---|
| 1ターン | 最初のターンの始まりから勝敗（試行の終わり）まで ÷ ターン数。内訳は LLM の返事を待った時間・移動と戦闘の演出（`move_fleet` と `end_turn` の実行時間）・そのほか |
| 返事 | LLM の返事の回数（1ターンあたり）と、セリフだけで操作をしなかった返事の回数 |
| 読み直し | キャッシュが効かずにプロンプト全体を読んだ返事（`cached_tokens` が 0）の回数と1回の秒数。サーバーが `cached_tokens` を返さないときは「—」 |
| 読み込み／生成の速さ | 読み直しの返事の「送ったトークン÷秒」の中央値（目安。最初の返事はモデルの読み込みが入るので除く）／読み直しなしの返事から当てはめた生成の速さ |
| 会話の継続 | ターンの始まりに前の会話を続けた回数と作り直した回数 |
| 失敗率 | AI が選んだ操作のうちゲームに断られた割合と、理由の内訳（資金不足・行動済みの艦隊・造船所がない など、文面から大まかに分ける）。同じ手を失敗の直後にもう一度呼んだ回数も |
| 空の返事・上限で切れた・断った・自動進行 | それぞれの回数 |

## 配信のしかた

1. MCPクライアント（のあ）を起動すると、サーバーが Chromium の窓でゲームを開きます。
2. OBS で「ウィンドウキャプチャ」にその窓を指定します。音はブラウザから鳴るので「アプリケーション音声キャプチャ」で拾います。
3. 字幕（`say`）と行動表示はゲーム画面の中に重ねて描くため、OBS 側の設定は要りません。

窓を閉じても、次のツール呼び出しで開き直します。ただし戦況は最初からになります。

## ツール一覧

| 種類 | ツール | 内容 |
|---|---|---|
| 情報 | `get_rules` | ルール要約（計算式つき）。最初に一度読む |
| | `get_summary` | 状況を短い日本語テキストで（小さなモデル向け） |
| | `get_state` | 全状況。自軍艦隊ごとの移動先候補（何が起きるか付き）、通信ウィンドウ、戦闘盤面も含む |
| | `get_screenshot` | 画面の画像（画像を読めるモデル向け） |
| | `get_next` | 「のこりの手」だけ（いまの資金で払える内政と、未行動の艦隊の行き先）。ai-player は、LLM が手を選べずにいるときに見せる |
| 演出 | `say` | セリフを字幕表示（操作ツールの `say` 引数でも出せる） |
| 共通 | `dismiss_dialog` | 通信ウィンドウを閉じる（下の行の「了解」「閉じる」などを押す。勝敗の結果画面では閉じるだけで、次のゲームは `new_game`）。通信は次の操作で自動的に閉じるので、ふつうは呼ばなくてよい |
| 作戦卓 | `move_fleet` `intercept` | 移動（戦闘に入ることもある）・迎撃 |
| | `invest_research` | 研究投資（30刻み、1ターンに120まで。多すぎる額は投資できる額に減らして実行） |
| | `refit_ship` `set_flagship` | 改装（sh/ca/mi/bo/sp の配分。書かない項目は今の値のまま）・旗艦指定 |
| | `set_formation` | 陣形（line 横陣／wedge 楔形／square 方陣／crane 鶴翼／rear 後衛陣）。いつでも変更でき、行動は消費しない |
| | `build_ship` `repair_fleet` `new_fleet` | 造船（追加か置換）・修理・新艦隊 |
| | `build_facility` `demolish_facility` | 施設の建設・撤去 |
| | `survey` `fortify` | 小惑星探査・防衛修復 |
| | `end_turn` `new_game` | ターン終了・やり直し |

小さなモデルでも操作を外しにくいよう、次のようにしています。

- 操作の返り値の `next` に「のこりの手」（いまの資金で払える内政と、未行動の艦隊の行き先）が入ります。打てる手が無くなると「end_turn でターンを終えてください」と返ります。内政は `build_ship(fleet_id=140, class_index=4) … 費用160` のようにIDつきの呼び出しの形で書き、費用は「費用N」と書きます（以前の「新艦隊(32)」の 32 を艦隊IDと読んで `build_ship(fleet_id=32)` を呼んだことがあった）。
- このターンに「払える」と見せた内政（状況テキストの「■内政の候補」や前の「のこりの手」）が、資金を使ったあと払えなくなったら、一度だけ `資金が足りなくなった手（呼ばない）：施設 mine60/lab70、第1艦隊にアークライト級を追加 費用160` のように書きます。前に見た一覧の手を、資金が減ったあとに呼んで断られることがあったためです（2026-11-17 のログで5回）。状況テキストの研究の行には、投資の上限まで入れたときの残りの資金も書きます（研究に120入れてから、一覧で見た造船を呼んで断られた）。
- 艦隊戦になる移動先と迎撃の欄には、戦力の比べから勝ち目（有利＝こちらが1.3倍以上／互角／不利＝0.9倍未満）を付けます（2026-11-16 のログでは、こちらが1.3倍未満の艦隊戦8回のうち4回負けていた（1.3倍以上は7戦全勝））。特性に合う施設がもう建っている星には「採掘所は建設済み」のように書きます。
- 断るとき（`ok: false`）は、理由と一緒に、いま選べるもの（行ける先・建てられる施設・迎撃できる艦隊など）を返します。
- AIプレイ（`ai-player.mjs`）では、断られた手と同じ手（名前と引数が同じ。`say` と引数の順は見ない）を、そのあと何の操作も成功しないうちにもう一度呼んだら、ゲームには送らずに「さっき断られた手と同じです（前の理由）」と返します。資金不足・行動済み・いまいる星への移動などは、何も変わらなければ同じ理由で断られるためです。操作が1つでも成功したら忘れます（施設を撤去してスロットが空く、のように通るようになることがあるため）。
- 通信ウィンドウは次の操作で自動的に閉じます。開いたときは返り値の `dialog`、操作のついでに閉じたときは `dialogs` に本文が入ります。
- 引数は寛容に読みます。数字は文字列でもよく、艦隊と星は名前（「第2艦隊」「リュネ」）でも、施設と陣形は日本語の名前（「採掘所」「方陣」）でも通ります。艦隊を名前で書いたときは名前で探します（名前の番号とIDは別物です）。足りない引数や読めない引数は、何を書けばよいかを日本語で返します。
- 公開する入力スキーマ（tools/list）もこれに合わせ、艦隊・星は「整数のID か 名前の文字列」（`anyOf`）、施設・陣形は英語キーと日本語名の両方を選択肢にしています。スキーマどおりに引数を検証するクライアントでも名前で送れます（前後の空白や英語キーの大文字はスキーマには書いていませんが、今までどおり読みます）。同梱の `ai-player.mjs` は、のあに見せる道具の説明が長くならないよう、今までどおり整数のIDと英語キーだけの形に絞って LLM に渡します。
- 操作は1つずつ順番に実行します。応答を待たずに続けて送った操作は、前の操作が終わってから実行し、そのときの状態で検査します（`new_fleet` を2件同時に送ると、2件目は「自軍艦隊は最大3つです」で断られます）。状態を読むだけのツールは待たずに答えます。
- 操作ツールの `say` 引数に書いたひとことは、操作の前に字幕に出ます。

戦術戦闘はオートで、`move_fleet` `intercept` `end_turn` は戦闘が決着して作戦卓に戻ってから返ります。返り値の `events` に結果の1行、`battles` に `{ title, result, rounds, lost, ships, downed, foes }` が入ります。`--manual-battle` のときだけ、次のツールが増えます。

| 種類 | ツール | 内容 |
|---|---|---|
| 戦術戦闘 | `battle_state` | 盤面（文字の盤面図、ユニット、各艦の移動先と攻撃候補・予測ダメージ） |
| | `battle_attack` `battle_move` `battle_wait` | 1隻ずつ行動 |
| | `battle_end_phase` `battle_retreat` `battle_close` | 敵フェイズへ・撤退・戦闘を閉じる |

行動系ツールはすべて同じ形で返ります。

```json
{ "ok": true, "message": "…", "events": ["この行動で起きたログ"], "funds": 120, "turn": 3,
  "mode": "map | battle | battle_ended | over", "dialog": {…}, "battle": {…}, "battles": [{…}] }
```

画面のボタンで押せない操作（資金不足、射程外など）は `ok:false` と理由が返ります。ゲームは進みません。

## のあ向けの指示（システムプロンプト例）

```
あなたは「辺境星系戦記」を実況プレイ配信しているのあです。
- 最初に get_rules を読み、各ターンの始めに get_state で状況を見る。
- 通信ウィンドウ（dialog）が出たら、内容を視聴者向けに要約する（通信は次の操作で自動的に閉じる）。
- 大きな判断（研究、攻める先、改装）の前に、理由を一言言う。操作と一緒に言うときは、その操作の say 引数に書く。
- 操作の返り値の next（のこりの手）から次の手を選ぶ。断られたら、一緒に返る「選べるもの」から選び直す。長考は避け、1ターンの操作は数回にまとめる。
- 戦闘はオートで決着し、結果が events に出る。結果をひとこと実況する。
  勝てる相手を選び、傷ついた艦隊は修理してから出し、相手に合わせて陣形を選ぶ。
- 惑星や巣の中枢は爆装でしか壊せない（巣の中枢はセラフ級の爆装だけ）。攻略に出す艦隊には爆装を積む。
```

## ゲーム本体への組み込み案（任意）

いまは Playwright が `game-api.js` を後から差し込むので、本体の変更は不要です。本体に同梱する場合は、本体の `<script>…</script>` の直後に次の1行を足すだけです。

```html
<script src="game-api.js"></script>
```

`game-api.js` は本体の以下の名前に依存しています。改名や仕様変更をする場合は、こちらも合わせて直す必要があります。

- 状態：`S`, `B`, `CLASSES`, `STATS`, `FAC`, `OWNER_LABEL`, `HIVE`, `BW`, `BH`
- 関数：`log`, `bmsg`（記録のため差し替える）, `render`, `renderBattle`, `planet`, `neighbors`, `fleetsAt`, `intruder`, `fleetPower`, `planetIncome`, `income`, `labRate`, `capOf`, `bcost`, `hasF`, `researchOpen`, `shipStats`, `makeShip`, `reach`, `bestAttack`, `unitAt`, `dist`, `isRock`・`docOf`・`FORM`・`FORM_KEYS`・`formKey`・`formOf`・`openFormation`（あれば使う）
- 行動：`orderMove`（演出つきの async。await して待つ）, `intercept`, `invest`, `openRefit`, `openYard`, `openBuild`, `closeModal`, `repair`, `newFleet`, `buildFac`, `demolish`, `survey`, `fortify`, `endTurn`, `newGame`, `doAttack`, `doMove`, `afterPlayerAct`, `enemyPhase`, `finishBattle`, `closeBattle`
- 要素：`#modal`, `#modalCard`（通信ウィンドウの検出と「了解」ボタン）
- 演出：`window.FAST`（`setPace(0)` で true にして、移動・攻撃・フェイズの演出を省く）。待機判定は `B.busy`／`B.phase` と `endTurn()` の完了で行う
