## B-01【高】ラウンド上限がなく、膠着した戦闘が終わらない

**場所**：`enemyPhase()` 1082–1105（`B.round++` は 1099 行。上限の判定がない）、`battleOver()` 1000–1007（勝敗は旗艦の撃沈だけで決まる）。原因の AI 側は `pickTile()` 1061–1081（B-02・B-03）。

**何が起きるか**：戦闘が終わる手段は、どちらかの旗艦が沈むか、自軍が「撤退」するかの2つしかない。どちらも近づかない形になると、いつまでもラウンドだけが進む。
- 自軍が防衛側（敵が攻めてきた戦闘）でも、終える手段は「突っ込む」か「撤退する」しかない。撤退すると敵がそのまま星を包囲する（1131 行の `siege`）。持ちこたえれば勝ち、という結末がない。
- MCP の自動進行 `ai-player.mjs` の `autopilot()`（248–264 行）は、200 手たっても戦闘が終わらないとループを抜けて `undefined` を返す。呼び出し側の 307–308 行 `if (s.over || ended)` がそこで TypeError を起こす。※コードを読んで確認しただけで、実行はしていない。

**膠着しやすい組み合わせ（実測）**
1. **自軍が完全に受け身（毎ラウンドすぐターン終了）の場合**（`t26.mjs`、各60戦、30ラウンドまで）

2. **砲撃戦隊で随伴の砲撃艦が沈み、旗艦（keep）だけが残った場合**：受け身の自軍に対して、20/20 戦で10ラウンド一歩も動かない（`t29.mjs`）。
3. **ai-player.mjs の autopilot と同じボット**（撃てるなら撃ち、撃てなければ敵旗艦へマンハッタン距離で近づき、近づけなければ待機）。5ドクトリン＋異生体 × 自軍の陣形5種、各24戦（`t25.mjs`、6ラウンド盤面が変わらなければ膠着と判定）：

   | 戦列／横陣・方陣 | 2・1（計3/120）|
   | 突撃・砲撃・強襲・異生体（全陣形）| 0 |

   膠着した盤面はすべて、両軍の旗艦を結ぶ行（y=3）に小惑星があり、ボットの艦が `#` の手前で止まっている。それに加えて、敵は重装（keep/guard で動かない）か、戦列（移動2の assault が小惑星の手前で止まる＝B-03）だった。例：
   ```

   ...........
   ..........e

   ..........e

   ...P#..#Ee.      ← 両軍とも小惑星の手前で止まる
   ```
4. **爆装0で惑星攻略戦**（B-05）：中枢と衛星は動かないので、自軍が射程外にいるかぎり何も起きない（20ラウンド回して双方無傷。`t2.mjs`）。

**再現手順（確認済み）**：`t16.mjs`。`startBattle({kind:"fleet",pf,ef:vargaFleet(..,"heavy"),attack:false})` のあと `battleEndPhase()` を30回くり返す → `B.round=31`、全艦が満タンの耐久のまま、`ended=false`。

**直し方の案**
- ラウンド上限を入れる（例：12）。`enemyPhase` で `B.round++` した直後に、
  ```js
  const MAX_ROUND=12;
  if(B.round>MAX_ROUND){B.busy=false;setFfwd(false);return finishBattle(B.cfg.attack?"timeout":"hold")}
  ```
  `finishBattle` の文言を足す（timeout＝「時間切れ：攻め切れず後退」、hold＝「時間切れ：敵は退いた」）。`closeBattle` は、

  あわせて、ヘッダーの表示を `ROUND n/12` にし、最終ラウンドに `bmsg("最終ラウンド")` を出す。
- フックも合わせて直す。`game-api.js` の `battleClose` の結果文言（489 行付近）は勝利・撤退以外を「敗北」と表示するので、新しい結果を足す。`RULES` にも上限を書く。`ai-player.mjs` の `autopilot()` は、ループの後に `return (await tool("get_state")).json` を返す。膠着を見つけたら `battle_retreat` で抜ける保険も付ける。
- AI 側の原因は B-02・B-03 で直す。上限は最後の保険にする。

## B-02【中】keep/guard 役が自分から近づかない（重装戦隊・砲撃戦隊の旗艦）

**場所**：`pickTile()` の `case"keep"`（1069 行）と `case"guard"`（1071–1073 行）。ドクトリンの定義は 288–289 行。

**何が起きるか**
- keep：`Math.max(0,4-nd)*3-…` なので、一番近い自軍艦との距離 nd が4以上なら評価は0で一定。良くなるマスがないので動かない（ミサイル持ちでも、1手で距離4まで行けないかぎり動かない）。
- guard：自軍旗艦の、一番近い敵との距離が6を超えているあいだは「旗艦の隣」にいるのが最善になり、その場に留まる。
- そのため重装戦隊（旗艦 keep・随伴 guard）は、**攻め込んできた側でも**右端で固まるだけになる（B-01 の 60/60）。説明の「盾艦が旗艦を囲んで守る」は守りの記述で、攻めてこないとは書いていない。

**再現**：B-01 の `t16.mjs`／`t26.mjs`／`t29.mjs`（確認済み）。

**直し方の案**：keep に「遠すぎるときは前に出る」項を足す。guard は今の式のままで旗艦について来る。
```js
case"keep":return (nd>6?(nd-6)*1.5:0)+Math.max(0,4-nd)*3-(inRange(c,nf)&&nd>=3?1:0);
```
攻め込んできた戦闘だけ前に出したいなら、`(!B.cfg.attack||B.round>=3)&&nd>6` を条件にする。こうすると集団は距離6まで寄り、そこで guard が `nearestOf(own,foes)[1]<=6` を満たして交戦に移る。

## B-03【中】敵 AI がマンハッタン距離で動くため、小惑星1個で足踏みする

**場所**：`pickTile()` 1066–1080 行（`dist(c,flag)`・`dist(c,t)`・`dist(c,nf)`）。1080 行は、評価が今より 0.05 以上良いときしか動かない。

**何が起きるか**：目標とのあいだの同じ行に小惑星が1個あるだけで、移動2の艦は回り込めない。回り込みの1歩目は距離が縮まらないので選ばれず、毎ラウンドその場で待機する。tier0 の戦列艦や重装艦は機関1（移動2）なので該当する。自軍艦が動かないと、これが永久に続く。同じ仕組みで、旗艦のすぐ後ろにいる随伴艦も前へ出られない（戦列で敵の行動の約10%が「何もしない」だった。`t14.mjs`）。

**再現（確認済み、`t28.mjs`）**：小惑星を (7,3) だけ、自軍のラーク (3,3)、敵 assault (8,3) にして `battleEndPhase()` を5回くり返す。
- move=2 のとき：`8,3 → 8,3 → 8,3 → 8,3 → 8,3`（動かない）
- move=3 のとき：`6,2 → 3,2`（回り込んで攻撃する）

**直し方の案**：目標からの歩数マップを BFS で作り、Manhattan 距離の代わりに使う。小惑星は壁にし、ユニットは通れるものとする。
```js
function stepMap(t){const m=new Map([[`${t.x},${t.y}`,0]]),q=[[t.x,t.y]];
  while(q.length){const[x,y]=q.shift(),d=m.get(`${x},${y}`);
    for(const[dx,dy]of DIRS){const nx=x+dx,ny=y+dy,k=`${nx},${ny}`;if(nx<0||ny<0||nx>=BW||ny>=BH||m.has(k)||isRock(nx,ny))continue;m.set(k,d+1);q.push([nx,ny])}}
  return c=>m.get(`${c.x},${c.y}`)??99}
```
`pickTile` の先頭で `const dF=stepMap(flag)` を作り、`default` と `flank` の `dist(c,flag)` を `dF(c)` に置きかえる（`inRange` の判定は射程の話なので dist のままでよい）。味方が道をふさぐ場合も扱うなら、味方のいるマスを +2 の重みにする。ai-player.mjs の autopilot も、同じ理由で `d(p)` を BFS の歩数にする。

## B-04【中】戦列・突撃の敵旗艦が先頭に立ち、最初に撃てる位置へ来る

**場所**：`enemyPhase()` 1088 行（行動順が `B.units` の並び＝旗艦から）。`DOC.line/assault.flagRole:"assault"`（286–287 行）。`pickTile` の default（1075 行）は旗艦も随伴艦も同じ式。突撃戦隊は初期配置 `[8,3]` で、旗艦が最前列にいる。

**何が起きるか**：旗艦が真っ先に、自軍旗艦めがけて一直線に動く。随伴艦は上下の列から出るので遅れ、旗艦の後ろで詰まる（B-03）。旗艦を沈めれば勝ちなので、事実上そのまま負け筋になっている。

**実測**
- 自軍が受け身（`t4.mjs`、30戦×5R）：旗艦が「敵の中で自軍に一番近い艦」だったラウンドは、戦列 100/128・突撃 85/91。最初に接敵した時点で旗艦が自軍の射程内にいたのは、戦列 21/30・突撃 28/30（砲撃・重装は 0/30）。
- 単純ボット（`t12.mjs`、25戦）：最初に沈んだ敵艦が旗艦だったのは、戦列 21/25・突撃 23/25。突撃戦隊戦は平均 2.3 ラウンドで決着した。

**直し方の案**
1. 行動順を随伴艦→旗艦にする：`for(const e of B.units.filter(u=>u.side==="E"&&u.hp>0).sort((a,b)=>(a.flag?1:0)-(b.flag?1:0)))`。
2. 旗艦が assault のときは、随伴艦より前に出ないようにする。`pickTile` の default で `e.flag` なら、
   ```js
   const esc=B.units.filter(u=>u.side==="E"&&u!==e&&u.hp>0&&u.move>0);
   if(esc.length){const front=Math.min(...esc.map(u=>nearestOf(u,foes)[1]));if(nd<front+1)s+=(front+1-nd)*2}
   ```
   を足す（s は今の default の式の値）。突撃戦隊の説明「旗艦めがけて突っ込んでくる」は、自軍の旗艦を狙うという意味なので、この直しと矛盾しない。

## B-05【中】爆装0では、惑星攻略戦・巣で勝つ手段がない（事前の警告もない）

**場所**：`bestAttack` 976 行（中枢には `w.core`＝爆装しか効かない）。`planetTip` 611 行（「惑星攻略戦」と出るだけ）。`orderMove` 638–640 行。`startBattle` 914 行（tip の文言は固定）。

**何が起きるか**：改装で全艦の爆装を0にした艦隊でも、警告なしで攻略戦に入れる。中枢は移動0で、衛星も動かないので、射程外にいれば永久に何も起きず（B-01）、近づけば一方的に撃たれる。爆装艦が戦闘中に全部沈んだ場合も同じで、勝てないことは画面のどこにも出ない。

**再現（確認済み、`t2.mjs`）**：第1艦隊の全艦を `a.bo=0` にする。`planetTip(planet(3))` は「右クリック：第1艦隊が惑星攻略戦」とだけ出る。`startBattle({kind:"planet",…})` のあと、中枢の隣に置いた旗艦の `bestAttack(pf,core)` は `null`。`battleEndPhase()` を20回くり返しても `ended=false`、全艦無傷。

**直し方の案**
- `planetTip` と右クリック移動（`onPlanetRight`/`orderMove`）で、目的地が `owner!=="P"` かつ艦隊がいない星で、`!f.ships.some(s=>s.a.bo>0)` のときは「爆装なし：中枢を破壊できません」と赤字で出す。移動前に確認を挟んでもよい。
- 戦闘中は `renderBattle` で `B.cfg.kind!=="fleet"&&!B.units.some(u=>u.side==="P"&&u.hp>0&&u.w.some(w=>w.core))` のとき、bTip と操作バーに「爆装を持つ艦がいないため中枢を破壊できません（撤退を推奨）」を出す。
- game-api.js の `rules`・サマリーにも同じ注意を書く。

## B-06【中】艦隊戦に勝つと敵の星に居座るが、その星を攻略できない

**場所**：`closeBattle` 1126 行（`if(cfg.attack&&!…)pf.node=cfg.node`）、`fleetCard` 528–534 行（ボタン）、`onPlanetClick` 581–584 行（今いる星は移動先に選べない）。

**何が起きるか**：敵艦隊がいる敵/中立/浸食（M）惑星や巣（H）へ攻め込んで艦隊戦に勝つと、艦隊はその星に移る。しかし星の持ち主は変わらず、攻略戦も始まらない。次のターン以降も、その場から攻略する命令がない（今いる星は移動先として選べず、ボタンは移動・改装・陣形だけ）。攻略するには、いったん隣の星へ出て戻る必要があり、2ターンかかる。巣の場合は、居座っている間に湧いた異生体と同じマスにいても戦闘にならない。

**再現（確認済み、`t3.mjs`）**：第1艦隊をオルド(4)に置き、`orderMove(f,9)`（クオン：E、ヴァルガ前衛がいる）で艦隊戦に入る → 敵旗艦を撃沈して `closeBattle()`。結果は `f.node=9`、`planet(9).owner="E"`、艦隊カードのボタンは「移動・改装・陣形」だけ。`f.moved=false` にして `onPlanetClick(9)` を呼んでも何も起きない。

**直し方の案**（どちらか）
- (a) `fleetCard` に「攻略」ボタンを足す。条件は `planet(f.node).owner!=="P"&&!intruder(f)` で、押すと `f.moved=true;startBattle({kind:p.owner==="H"?"hive":"planet",pf:f,planet:p,node:f.node,attack:true})`。行動を1回使う。game-api.js にも同じコマンドが必要。
- (b) 艦隊戦の勝利後に、その場で攻略戦へ進むか聞く（`closeBattle` の後に showComm で選ばせる）。

## B-07【中】「敵の射程」の斜線と「次に攻撃してくる範囲」の説明が実際より広い

**場所**：`threatOf` 961 行（今の位置＋移動できる全マスからの射程）。`renderBattle` 1197 行（危険範囲の表示）・1213 行・1266 行（「斜線のマスが次に攻撃してくる範囲」）。敵の行動は `enemyDecide` が `{attack}` か `{move}` のどちらか一方だけを返す（1057–1059 行、1093 行）。

**何が起きるか**：敵も自軍と同じで、1手番に移動か攻撃のどちらか一方しかできない。そのため次の敵フェイズで撃たれるのは「今の位置からの射程」に入っているマスだけなのに、斜線は移動してからの射程まで塗っている。「ここなら次のターンは安全」という一番大事な判断が、表示からはできない。

**再現（確認済み、`t7.mjs`）**：40戦。毎ラウンド、斜線の中にいるが今の位置からの射程には入っていない自軍艦を記録し、次の敵フェイズで被弾したかを数えた → **100件中0件**が被弾。

**直し方の案**：2層に分けて表示する。「次の敵フェイズに撃たれる」＝`rangeCells(e,[[e.x,e.y]],e.w.filter(w=>w.unit))` を濃い斜線に、「その次（敵が動いた後）」＝`threatOf(e)` からそれを引いた残りを薄い点線にする。凡例と、1266 行・遊び方（736 行）の文言も合わせて直す。

## B-08【低】異生体（改）の予測ダメージの「側／背」表示が逆の意味になる

**場所**：`renderBattle` 1241 行（`a.zone!=="正面"` なら頭文字を付ける）、凡例 1273 行（「側/背＝側面・背面ボーナス」）、`unitTip` 625 行、`mult` 969 行（改は 正面1.6／側面0.9／背面0.9）。

**何が起きるか**：改の側面に向けた攻撃は「-4側」と表示されるが、実際は×0.9 の減衰になっている。正面からの攻撃（×1.6）には何も付かない。通常の異生体でも、背面（×1.0）に「背」が付く。命中演出（1521 行）は `mult>1` で判定しているので、そちらは正しい。

**再現（確認済み、`t6.mjs`）**：`S.evolved=true` の群れ。ブルード改を左向き（dir 2）で (6,3) に置く。正面 (5,3) の旗艦から見ると `dmg 7, zone 正面, mult 1.6`、ラベルは「-7」。側面 (6,2) の艦から見ると `dmg 4, zone 側面, mult 0.9`、ラベルは「-4側」。

**直し方の案**：ラベルの判定を、ゾーン名ではなく倍率で行う。`const m=mult(ghost,u);` として、`m>1` なら「+」の印やゾーン名、`m<1` なら「弱」などを付ける。unitTip も同じにし、凡例を「末尾の印＝向きによるボーナス」に変える。

## B-09【低】後衛陣の「ミサイルのダメージ+1」が +0 になることがある

**場所**：`bestAttack` 979 行（+1 は倍率と装甲を掛ける前に足されるので、四捨五入で消えることがある）。サイドパネル 1261 行と unitTip 619 行は `w.d` をそのまま表示する。

**再現（確認済み、`t18.mjs`）**：ミサイル4（mi=1）、装甲3の敵を正面から距離3で撃つ。横陣・後衛陣どちらも 3 ダメージ。パネルの表示もどちらも「ミサイル 4」。

**直し方の案**：+1 を最後に足す（`dmg=Math.max(1,Math.round(dmg))+(rear&&missile?1:0)`）か、説明を「ミサイルの威力+1（装甲で減ることがある）」に変える。パネルとツールチップは、後衛陣のときだけ `w.d+1` を表示する。

## B-10【低】移動アニメの最後に向きが跳ぶ

**場所**：`doMove` 999 行（`face(u,x,y)` は始点から終点への全体の向き）、`animateMove` 1561–1569 行（区間ごとの `adir` で描き、最後に `adir=null`）。

**再現（確認済み、`t8.mjs`、FAST=false）**：移動3の艦で (1,3)→(3,2)。経路は `(2,3),(3,3),(3,2)` で、アニメ最後の区間の向きは 3（上）。終了後の `dir` は 0（右）。最後のコマで、上向きから右向きへ一瞬で回る。

**直し方の案**：ルール上の向き（全体の向き）は今のままにし、アニメ側を合わせる。たとえば `animateMove` の最後の 80ms で `adir` を最終の `dir` へ回す。または、`bpath` が主軸方向の移動で終わる経路を選ぶよう、DIRS の探索順を主軸が後になるように並べる。

## B-11【低】演出中の再描画で、エフェクトが途中で消える

**場所**：キー R（1634 行）・「敵の射程」ボタン（1252 行）・リサイズ（1651 行）。これらは `B.busy` 中でも `renderBattle()` を呼び、`svg.replaceChildren` が演出用の `<g>` まで消してしまう。

**再現（確認済み、`t19.mjs`）**：攻撃のビーム発射中に R キーを送る → エフェクトの線の数が 3 から 0 になる。撃沈の演出中なら、フェードしていた艦が一瞬元に戻って見える。

**直し方の案**：`B.busy` 中は `B.danger` を切り替えるだけにし、描画は次の通常の描画に任せる（`if(!B.busy)renderBattle()`）。または、盤面とユニット用の `<g>` だけを作り直し、演出用のレイヤーは残す。

## B-12【低】沈めた艦のツールチップが残る

## B-13【低】敵の翼の艦が、小惑星に囲まれて開始位置から動けないことがある

## B-14【低】「撤退」に確認がない

## 確かめて問題がなかったこと
- **予測ダメージと実際のダメージ**：陣形5種・ドクトリン・異生体（通常と改）、ランダム配置で 112 件比べ、すべて一致（`t10.mjs`。盤上の「-N」を読んで、実際の耐久の減りと比べた）。方陣の-25%・鶴翼の+15%・Seraph の特効も、予測と実際で同じ計算になっている。
- **楔形**：1ラウンド目は自軍だけ移動+1。敵フェイズの後に元へ戻り、2ラウンド目以降も戻ったまま。艦のデータ（ship）側は書き換えない（`t21.mjs`）。
- **ドクトリンの配置と上下反転・異生体の陣形**：重なりはなく、旗艦は index 0。小惑星とユニットの重なりも 0（`t5.mjs`）。
- **惑星攻略戦の衛星数**：`min(6,1+floor(def/14)+衛星群)` のとおり（ミラ2、クオン・ドラン・ヴァルガは6）。中枢・浸食核・巣の勝利と占領も正しく処理される（`t15.mjs`）。
- **スマホ縦向き**：自軍の dir 0 は `rotate(-90)`＝上（敵の方）、敵の dir 2 は `rotate(90)`＝下を向く。移動アニメの `adir` も正しい（`t11.mjs`、`port.png`）。
- **早送り**：敵フェイズ中にクリックすると速くなり（6.3秒→2.3秒）、終わると `ANIM.fast` も早送り表示も元に戻る（`t20.mjs`）。
- **演出中の連打**：FAST=false で、艦隊戦4種と惑星戦を、左右クリック・キー（W/E/R/Esc/1〜3）のランダム連打で進めた。同じラウンドに同じ艦が2回動くことはなく、例外も出なかった（`t23.mjs`/`t24.mjs`）。
